# product_alignment

3D 스캔에서 뽑은 측정점을 깨끗한 제품데이터 이미지 위로 옮긴다. 보정시트에 들어가는
그림은 편차 히트맵이 아니라 제품데이터 렌더이므로, 두 이미지 사이의 좌표 변환이
필요하다. 이 단계는 좌표만 옮기며 편차값을 보정치로 바꾸지 않는다.

## 왜 별도 입력이 필요한가

제품데이터는 품번당 한 장으로 고정이고 스캔은 차수마다 새로 생긴다. 그래서 제품데이터는
매번 올리는 입력이 아니라 품번에 등록해 두는 자산으로 다룬다. 한 번 등록하면 이후
스캔은 파일 하나만 올려도 자동으로 짝이 맞는다.

품번은 사내 파일명 규칙(`차종_품번_품명_공정_날짜`)에서 그대로 뽑는다.
`JD_64XX2-DR000 3D 스캔.png`와 `64XX2-DR000 제품데이터.png`는 모두 `64XX2-DR000`이 된다.
변형 코드가 어긋난 짝(`67XX6-DR000` 스캔과 `67XX6-DR050` 제품데이터)은 하이픈 앞
공통 부분으로 연결하고, 정확히 일치하지 않았다는 사실을 경고로 남긴다.

## 정렬 방법

두 이미지 모두 축에 정렬된 정투영 렌더라 변환은 축별 배율·평행이동과 반전 네 가지
조합뿐이다. 임의 각도 회전은 다루지 않는다.

```text
스캔 마스크 ─┐
             ├─ 좌우/상하 반전 4가지 × 바운딩박스 상사변환
제품 마스크 ─┘        └→ 외곽 IoU + 구멍 IoU + 2 × 경계밴드 IoU 로 채점
                            └→ 최고점 방향 채택, 2위와의 격차를 신뢰도로 보고
```

- **외곽 실루엣**은 배율과 위치를 잡는다. 실측 3개 품번에서 정방향 IoU는 0.973 ~ 0.990이었다.
- **내부 구멍**은 좌우를 가른다. 외곽선만으로는 좌우 반전이 구분되지 않는다.
- **경계 밴드**는 방향을 가르는 작은 노치를 키운다. 전체 면적 IoU에서는 묻히기 때문이다.

## 배율 보정

bbox끼리 맞추면 두 마스크가 가장자리에 무엇을 포함하는지가 그대로 배율에 섞인다.
스캔 마스크는 안티앨리어싱 보정으로 한 겹 팽창돼 있고, CAD 렌더는 검은 외곽선을
품고 있다. 그 차이가 부품을 조금 축소시켜 전사된 좌표가 전부 안쪽으로 당겨진다.

방향을 정한 뒤 축별 배율과 이동을 조금씩 바꿔 가며 겹침이 가장 큰 값을 찾는다.
구멍 중심의 반경 방향 오차로 측정한 효과는 다음과 같다.

| 품번 | 보정 전 | 보정 후 |
|---|---:|---:|
| 64XX2 | -3.35px | +0.02px |
| 71XX2 | -1.14px | -0.24px |

음수는 안쪽으로 당겨졌다는 뜻이다. 보고되는 `outline_iou` 등은 모두 보정된
변환 기준이고, `candidates`의 점수는 방향 판정에 쓴 bbox 변환 기준이다.

## 방향은 자동으로 확정하지 않는다

상하좌우가 거의 대칭인 부품은 네 방향의 점수가 거의 같아진다. RING SUNROOF(`67XX6`)는
1위와 2위의 격차가 0.045로, 사실상 자동 판정이 불가능하다. 나머지 두 품번은 0.96과
1.13으로 명확했다.

그래서 이 모듈은 격차가 `MIN_DECISION_MARGIN` 미만이면 `confident`를 False로 두고
경고를 남긴다. 보정시트는 하형 기준이라 좌우가 뒤집히면 금형을 반대로 깎게 되므로,
모호한 경우는 추정하지 않고 보고한다. 사람이 확정한 방향은 품번별로 저장돼 이후
스캔에 자동 적용된다.

외형 IoU가 `MIN_OUTLINE_IOU` 미만이면 확정 저장된 방향이 있더라도 `confident`는
False다. 사람이 정할 수 있는 것은 방향이지 부품이 같은지 여부가 아니다.

## 실행

```powershell
.venv\Scripts\python.exe product_alignment/run.py `
  --scan "path/to/JD_64XX2-DR000 3D 스캔.png" `
  --product "path/to/64XX2-DR000 제품데이터.png" `
  --out data/intermediate/64XX2_composed.png `
  --overlay-out data/intermediate/64XX2_overlay.png
```

`--product`를 생략하면 스캔 파일명의 품번으로 `data/product/`에서 찾는다.
`--register`는 제품데이터를 품번에 등록하고, `--confirm`은 이번 방향을 확정 저장한다.
`--flip-x`/`--no-flip-x`(상하도 동일)로 방향을 직접 지정할 수 있고, `--use-saved`는
확정 저장된 방향을 사용한다.

| 옵션 | 결과 |
|---|---|
| `--out` | 제품데이터 위에 포인트를 찍은 합성 이미지 |
| `--overlay-out` | 두 실루엣을 겹친 정렬 확인용 이미지 (빨강=스캔만, 자홍=제품만) |

## 출력

`Alignment`는 2×3 변환 행렬과 함께 판단 근거를 모두 들고 다닌다.

| 필드 | 의미 |
|---|---|
| `matrix` | 스캔 픽셀 → 제품데이터 픽셀 변환 (row-major 2×3) |
| `flip_x`, `flip_y` | 채택한 반전 |
| `outline_iou`, `hole_iou`, `band_iou` | 채점에 쓴 세 가지 일치도 |
| `margin` | 1위와 2위 방향의 점수 차 |
| `confident` | 자동 판정을 기본값으로 제시해도 되는지 |
| `overridden` | 방향을 사람이 지정했는지 |
| `warnings` | 확인이 필요한 이유 |

## 저장 위치

| 경로 | 내용 |
|---|---|
| `data/product/{품번}.png` | 등록된 제품데이터 이미지 |
| `data/alignment/{품번}.json` | 확정된 방향과 변환 |

둘 다 회사 자료라 저장소에 커밋하지 않는다.

## 현재 제약

- 임의 각도 회전과 원근 차이는 다루지 않는다. 두 렌더의 카메라가 다르면 실패한다.
- 배율 보정은 겹침을 최대화할 뿐이라, 두 마스크의 차이가 균일한 팽창뿐인 합성
  입력에서는 개선이 없거나 미세하게 나빠질 수 있다. 실제 품번에서는 3개 모두
  개선됐지만 표본이 셋뿐이다.
- 배율은 바운딩박스에서만 구하므로, 스캔에 부품 밖 요소가 붙어 외곽 상자가 커지면 어긋난다.
- 대칭 부품의 방향은 원리상 이미지만으로 정할 수 없다. 사람의 확인이 유일한 답이다.
- 검증에 쓴 품번이 3개뿐이라 임계값은 아직 넉넉히 잡혀 있다.
