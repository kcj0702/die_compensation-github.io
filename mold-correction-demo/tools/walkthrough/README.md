# 실행 녹화 → 해설 영상

화면 녹화 하나를 받아 **자막 달린 MP4** 와 **인터랙티브 해설 HTML** 로 만든다.
발표에서 "이 화면에서 무엇을 누르면 어떤 코드가 도는지"를 보여 주려고 만들었다.

## 왜 필요한가

녹화 원본은 손이 멈춰 있는 시간이 절반 가까이 된다. `보정치생성.mp4` 는 8분 26초인데
0.5초 간격 프레임 차이로 재보면 4초 이상 정지한 구간만 20군데, 합쳐서 130초였다.
그대로 틀면 발표에서 못 쓰고, 전체를 같은 배속으로 당기면 결과가 뜨는 순간까지
같이 날아간다. 그래서 **구간마다 배속을 다르게** 준다.

- 손이 멈춘 구간 · 같은 화면을 계속 보는 구간 → 최대 9.5배
- 버튼을 누르는 순간 · 결과가 뜨는 순간 → 1.3 ~ 2배

`보정치생성.mp4` 기준 8분 26초 → **2분 42초**.

## 쓰는 법

```bash
python build.py --video "녹화.mp4" --cues cues_보정치생성.py \
                --name 보정치생성 --out "C:/Users/<사용자>/Desktop/실행영상_해설"
```

`imageio-ffmpeg` 만 있으면 된다 (`pip install imageio-ffmpeg`). ffmpeg 를 따로
설치하지 않아도 번들 바이너리를 찾아 쓴다.

결과는 `--out` 폴더에 네 개가 떨어진다.

| 파일 | 쓰임 |
|---|---|
| `<이름>_자막포함.mp4` | PPT 에 넣거나 그냥 재생 — 자막이 영상에 구워져 있다 |
| `<이름>_영상.mp4` | 자막 없는 편집본 — 아래 HTML 이 이걸 쓴다 |
| `<이름>_해설.html` | 자막 · 목차 · 짚어주기 표시가 붙은 페이지 |
| `<이름>_자막.srt` | 따로 쓸 일이 있을 때 |

중간 파일은 `<out>/_build` 에 남는다. 대본만 고치고 다시 돌리면 바뀐 구간만
다시 자르므로 금방 끝난다. 전부 다시 자르려면 `--recut`.

## 대본 쓰기

`cues_보정치생성.py` 의 `SEGMENTS` 가 전부다. 한 줄이 곧 한 구간이자 한 자막이다.

```python
(186.0, 201.0, 2.50,
 "보정 계수 슬라이더 — 1.00× 에서 0.70× 로 내린다",
 "보수적 0.50 · 기준 1.00 · 적극적 1.50. 현장 판단을 그대로 반영한다",
 (85, 31)),
```

- `186.0, 201.0` — 원본에서 잘라 올 구간(초)
- `2.50` — 이 구간 배속
- 큰 줄 — 무엇을 하는지
- 작은 줄 — 그때 어떤 코드가 도는지
- `(85, 31)` — HTML 에서 동그라미로 짚어 줄 자리 (화면 대비 %). 없으면 `None`

### 대본을 쓸 때 지킨 것

- **영상에서 실제로 일어난 일만 적는다.** 프레임을 3~6초 간격으로 뽑아 눈으로
  확인했고, 같이 적은 코드 경로는 저장소에서 확인한 것이다.
- **누르는 자리가 없는 구간에는 짚어주기 표시를 달지 않는다.** 화면이 스크롤되는
  구간도 마찬가지다 — 고정 좌표가 엉뚱한 곳을 가리키게 된다.
- **한 자막은 4초 이상.** 그보다 짧으면 두 줄을 읽을 수 없어서, 배속을 낮추거나
  앞 구간과 합친다.

## 커밋하지 않는 것

녹화 원본과 결과 MP4 에는 실제 품번과 보정 시트가 그대로 찍혀 있다.
`data/product`, `data/template` 과 같은 회사 자료이므로 저장소에 올리지 않는다.
이 폴더에는 **대본과 도구만** 둔다.
