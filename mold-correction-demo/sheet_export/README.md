# sheet_export

보정시트를 사내 엑셀 양식(.xlsx)으로 내보낸다. 값은 그림에 구워 넣지 않고
**엑셀에서 클릭해 수정할 수 있는 텍스트박스**로 만든다.

## 사내 시트가 실제로 어떻게 생겼는가

기존 보정시트 엑셀을 뜯어보면 (포인트, 보정량) 표가 아니라 시트 위에 배치한 도면이다.

| 요소 | 실체 | 실측 개수 |
|---|---|---|
| 표제란 | 진짜 셀 (`M1`, `Y1`, `M3`, `Y3`, `M5`, `Y5`) | 6칸 |
| 도면 | 그림 객체 `<pic>` | 9 ~ 11개 |
| 편차값 | 텍스트박스 `<sp>` | 147 ~ 182개 |
| 지시선 | 연결선 `<cxnSp>` | 68 ~ 96개 |

`보정시트_양식.xlsx`는 표제란 라벨과 병합 셀 13개만 있는 빈 서식이다.

## 어떻게 만드는가

openpyxl은 그림과 셀만 쓸 수 있고 텍스트박스·연결선은 만들지 못한다. 그래서 둘로 나눈다.

```text
1) openpyxl  → 양식 열기, 표제란 셀 채우기, 뷰 이미지 배치
                (media 파트와 관계 파일까지 알아서 처리된다)
2) 직접 주입 → drawing 파트에 텍스트박스와 지시선 anchor 를 덧붙인다
```

**주의할 점 하나.** openpyxl은 spreadsheetDrawing을 *기본 네임스페이스*로 쓴다
(`<wsDr>`, `<pic>`). 원본 파일처럼 `xdr:` 접두사를 붙여 넣으면 Excel이 도형을
통째로 무시한다. 이 모듈은 접두사 없이 쓰고, 그 계약을 테스트로 고정해 두었다.

좌표는 EMU다. 1인치 = 914400 EMU = 96px 이므로 1px = 9525 EMU.
배치는 `absoluteAnchor`를 쓴다. 행·열 크기가 바뀌어도 도면이 흐트러지지 않는다.

## 라벨 배치

값이 부품 위에 얹히면 도면을 가린다. 원본 시트처럼 **가장 가까운 변의 여백으로
보내고 지시선으로 잇는다.** 같은 변에 몰리면 최소 간격만큼 밀어낸다.

## 사용

```python
from sheet_export import SheetPoint, SheetView, TitleBlock, build_sheet, crop_view

points = [SheetPoint("P-01", "-0.7", x_ratio=0.31, y_ratio=0.62), ...]
front = SheetView(image=product_image, points=points)
detail = crop_view(product_image, points, (0.0, 0.3, 0.26, 0.7), "DETAIL A")

report = build_sheet([front, detail], TitleBlock(part_no="64XX2-DR000"),
                     output=Path("보정시트.xlsx"))
```

`x_ratio`/`y_ratio`는 그 뷰 이미지 대비 0~1이다. `crop_view`는 영역 밖 포인트를
버리고 안쪽 포인트의 좌표를 잘라낸 이미지 기준으로 다시 계산한다.

`text`는 그대로 인쇄된다. **편차를 보정치로 바꾸는 계산은 이 모듈이 하지 않는다.**
부호와 계수는 호출하는 쪽에서 정해 넘긴다.

## 양식 파일

`data/template/보정시트_양식.xlsx`에 두면 자동으로 쓴다. 없으면 빈 통합문서로
만들고 그 사실을 `BuildReport.warnings`에 남긴다. 회사 자료라 커밋하지 않는다.

## 현재 제약

- openpyxl이 양식의 기존 도형과 프린터 설정을 저장 과정에서 버린다. 양식에 있던
  빈 도형 2개가 사라지고 인쇄 설정은 기본값이 된다.
- 라벨 배치가 기계적이다. 원본 시트는 사람이 도면을 보며 위치를 잡은 티가 난다.
- 제로라인 폴리라인은 아직 넣지 않는다.
- 뷰가 많아 라벨이 여백을 넘치면 시트 밖으로 밀려날 수 있다. 개수 제한은 없다.
