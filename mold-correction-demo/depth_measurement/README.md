# 금형 보정 데모 · 형상 특징 추출

3D 스캔 편차 히트맵 **이미지 한 장**에서 부품 형상 · 형상 특징 · 편차값을 추출하고,
보정치 산출 직전 단계의 통합 데이터를 생성한다.

담당 파트: **기능 5 — 깊이 / 형상 특징 파악**
데모 범위: **형상 특징 · 편차 추출까지**. 보정치 산출은 포함하지 않는다 (회의 합의 사항).

---

## 실행

저장소 루트(`mold-correction-demo/`)에서 실행한다.

```bash
pip install -r depth_measurement/requirements.txt
streamlit run depth_measurement/streamlit_app.py
```

브라우저가 열리면 우측 상단에서 샘플을 선택하거나 스캔 이미지를 업로드한다.
좌우 반전된 캡처는 사이드바의 **좌우 반전** 토글로 정규화한다 (기본 ON).

샘플은 `data/sample/` 에서 읽는다. 이 경로는 `.gitignore` 대상이므로
**회사 스캔 이미지는 저장소에 커밋되지 않는다.** 로컬에서 직접 넣어 사용한다.

## 파이프라인

```
스캔 편차 히트맵 (PNG)
   │
   ├─① 형상 추출      배경·컬러바·지시선·라벨박스 제거 + inpaint 복원
   ├─② 정면도         색을 벗겨 실제 음영만 남긴 단색 뷰
   ├─③ 릴리프         하이패스로 저주파 제거 → 비드·필릿·형상선 강조
   ├─④ 형상 특징 검출  홀(원/사각/기타) · 형상선 · 평면 영역
   └─⑤ 편차 조회      컬러바 자동 검출 → 색을 mm 로 역변환, 클릭/hover 조회
```

각 단계의 결과 이미지는 화면에서 PNG 로 내려받을 수 있다.

### 왜 형상 특징이 필요한가

보정치는 두 개의 서로 다른 정보가 만나 결정된다.

| | ① 편차 (deviation) | ② 형상 특징 (feature) |
|---|---|---|
| 무엇 | 기준면에서 얼마나 틀어졌나 (mm) | 그 자리가 어떻게 생겼나 |
| 역할 | 보정의 **크기** | 보정의 **계수 · 방식** |
| 담당 | 기능 3 (포인트 추출) | **기능 5 — 본 파트** |

같은 −1.0mm 편차라도 평면 위인지 비드 위인지에 따라 스프링백이 달라 보정 계수가 달라진다.
이번 데모는 이 두 축을 **각각 추출하는 것까지** 다룬다. ⑤ 편차 조회에서 한 지점을 클릭하면
그 자리의 편차와 형상 특징이 함께 표시되어 두 축이 어떻게 만나는지 확인할 수 있다.

두 축을 좌표 단위로 결합한 테이블 생성 로직은 `pipeline.py` 에 구현되어 있으나
(`build_point_table`), 데모 범위를 넘어서므로 화면에는 노출하지 않는다.

## 기술 배경 — 깊이 추정 대신 릴리프를 쓴 이유

기능 5의 원래 구상은 **단일 RGB 이미지 깊이 추정(Depth Anything 계열)으로 3D 형상을 복원**해
형상 특징을 얻는 것이었다. 검증 결과 부적합해 릴리프 기반으로 전환했다.

### 깊이 추정이 실패한 이유

세 가지 입력으로 실험했고 모두 부품이 평면으로 뭉개졌다.

| 실험 | 입력 | 결과 |
|---|---|---|
| 1 | 컬러 히트맵 원본 | 평면 |
| 2 | 단색 변환본 (실제 음영 노출) | 평면 |
| 3 | 대비 강조본 (CLAHE + 언샤프) | 평면 |

**실험 2가 결정적이다.** 단색 변환본은 금속 실사진처럼 보이고 굴곡도 육안으로 확인되는데도
결과가 같았다. 즉 원인은 "가짜 색이라 모델이 못 알아본다"가 아니다.

**진짜 원인은 스케일 불일치다.**

| | 크기 |
|---|---|
| 부품 폭 | 약 1,000 mm |
| 검출 대상 (비드 · 필릿) | 약 0.5 mm |
| 비율 | **1 / 2,000** |

모노큘러 깊이 추정 모델은 장면 규모(scene-scale) 깊이를 위해 설계되었다. "사람이 2m 앞,
벽이 5m 뒤" 수준의 해상도로는 1/2000 크기의 요철을 표현할 수 없다. 실험 3에서 대비를
극단적으로 올려도 결과가 변하지 않은 것이 이를 뒷받침한다 — 입력 품질 문제였다면
개선되었어야 한다.

여기에 두 가지가 겹친다. 모델은 학습 과정에서 익힌 **크기 사전지식**으로 깊이를 역산하는데
자동차 대시패널은 학습 대상이 아니었고, 이미지에 **축척 기준물**도 없다.
(회의록 2번의 "실제 제품 사진에는 기준값이 없다"가 같은 문제다.)

### 릴리프란 무엇인가

이미지 밝기를 주파수 성분으로 분해한다.

| 성분 | 정체 |
|---|---|
| 저주파 | 전체 곡률, 조명 기울기, 큰 굴곡 — 천천히 변함 |
| 고주파 | 비드, 필릿, 형상선, 미세 요철 — 급격히 변함 |

찾으려는 형상 특징은 전부 고주파이므로 저주파를 제거하면 된다.
가우시안 블러가 저주파 추출기 역할을 한다.

```python
low    = cv2.GaussianBlur(gray, (0, 0), sigma)   # 미세 성분이 뭉개져 저주파만 남음
relief = gray - low                              # 뭉개진 성분 = 고주파만 남음
```

산맥 위에 자갈이 흩어진 지형에 비유하면, 블러는 자갈을 지우고 능선만 남긴 지도이고,
원본에서 그것을 빼면 능선이 사라지고 자갈만 남는다.

### 왜 릴리프는 동작하는가

| | 깊이 추정 | 릴리프 |
|---|---|---|
| 묻는 질문 | 카메라에서 몇 mm 떨어졌나 | 주변보다 밝은가 어두운가 |
| 필요한 것 | 축척 · 크기 사전지식 · 절대 기준 | 없음 |
| 성질 | 절대값 | 국소 상대값 |

릴리프는 각 픽셀을 자기 주변하고만 비교한다. 부품 종류 · 실제 크기 · 조명 조건을 알 필요가
없으므로 깊이 추정을 막았던 세 가지 벽이 모두 해당되지 않는다.

또한 이 음영은 우리가 만든 것이 아니다. **스캔 뷰어가 3D 메시에 조명을 계산해 명암을 입힌 뒤
편차를 색으로 덧칠했으므로, 음영 자체가 이미 3D 정보다.** 3D→2D 투영은 렌더러가 이미 수행했고,
② 정면도는 그 위에 덮인 색을 벗겨 음영을 드러내며, ③ 릴리프는 거기서 고주파를 분리한다.
없던 정보를 생성하는 것이 아니라 묻혀 있던 정보를 복원하는 방식이다.

### 릴리프의 한계

릴리프는 깊이가 아니라 국소 명암 대비다. 따라서 **형상 특징의 위치는 주지만 치수는 주지 못한다.**
비드가 어디 있는지는 알 수 있어도 몇 mm 깊은지, 필릿 R값이 얼마인지는 알 수 없다.
정확한 치수가 필요하면 CAD 또는 3D 스캔 원본이 있어야 한다.

### 정합에 대한 재정리

회의록 5번의 문장을 목적과 수단으로 분리하면 다음과 같다.

> "깊이를 측정해 형상을 CAD 데이터와 맞추면 (수단) / 어느 부위가 어디인지 잡아낼 수 있다 (목적)"

**목적은 CAD 정합이고 깊이 추정은 그 수단이었다.** 3D끼리 맞추는 표준 방법(ICP)을 쓰려면
스캔 쪽도 3D여야 하므로 2D를 3D로 올리는 다리로 깊이 추정을 상정한 것이다.

수단은 부적합했지만 목적은 유효하며, **특징점 기반 2D 정합**이라는 대체 경로가 있다.
3D 복원 없이 양쪽에서 같은 지점을 찾아 변환을 계산하는 방식이고, 여기에 필요한 랜드마크는
④ 형상 특징 검출에서 이미 확보했다 — 대시패널은 원형 홀과 사각 창이 풍부해 정합에 유리하다.

정합이 완료되면 필릿 R값 같은 형상 정보는 CAD에서 직접 읽을 수 있으므로,
릴리프 기반 추정을 설계 정답으로 대체하게 된다.

## 형상 특징 분류 규칙

**홀** — 부품 안쪽의 흰 영역 컨투어를 기하로 분류한다.

| 종류 | 판정 |
|---|---|
| `circle` | 원형도 ≥ 0.85 **AND** bbox 종횡비 < 1.30 **AND** 최소외접원 채움도 ≥ 0.75 |
| `rect` | bbox 채움도 > 0.72 **AND** 종횡비 < 5.0 |
| `other` | 위 두 조건에 해당하지 않음 |

정사각형은 원형도 π/4 ≈ 0.785, 최소외접원 채움도 2/π ≈ 0.637 이므로
세 조건 조합으로 원과 확실히 분리된다.

**표면** — 릴리프의 국소 표준편차로 구분한다.

| 종류 | 판정 |
|---|---|
| `near_edge` | 검출된 형상선에서 14px 이내 |
| `bead` | 릴리프 국소 표준편차 > 26 |
| `flat` | 평면 마스크에 포함되거나 국소 표준편차 < 8 |
| `surface` | 그 외 일반 곡면 |

## 편차 복원 방식

히트맵의 색 자체가 편차값이므로, 컬러바를 대응표(LUT)로 삼아 역변환한다.

1. 부품 바깥 좌/우 20% 영역에서 채도가 높고 세로로 긴 영역을 컬러바로 자동 검출
2. 컬러바 중앙선을 256단계로 샘플링해 **색 → mm** 대응표 생성
3. 부품의 모든 픽셀을 **Lab 색공간** 최근접 매칭으로 mm 값에 대응

컬러바 눈금의 min/max 는 스캔마다 다르므로 사이드바에서 입력한다 (기본 −1.5 ~ +2.0).

## 알아야 할 한계

### 원리상의 한계

- **상대 릴리프까지만 가능하다.** 정확한 필릿 R값, 릴리프 깊이(mm), 부품 전체 3D 형상은
  단일 히트맵에서 얻을 수 없다. 정밀 형상이 필요하면 CAD 또는 3D 스캔 원본이 있어야 한다.
- **모노큘러 깊이추정(Depth Anything 등)은 이 부품에 부적합하다.** 근거는 위
  「기술 배경」 참조. 이 트랙에는 시간을 쓰지 않는다.
- **편차는 컬러바 해상도만큼만 정밀하다.** 라벨이 붙은 지점의 정확한 실측값은
  `deviation_extraction` 파트(VLM 판독)의 결과가 더 정확하며, 본 파트의 값은
  라벨이 없는 지점까지 표면 전체를 채우는 조밀한 근사장이다. 두 결과는 상호보완적이다.

### 검증 상태 — 아직 확인하지 않은 것

동작은 확인했으나 **정확도는 검증하지 않았다.** 현재까지의 검증 범위는 다음과 같다.

| 항목 | 상태 |
|---|---|
| 부품 3종에서 예외 없이 실행 | ✅ 확인 |
| 형상 추출 · 라벨 제거 결과 (육안) | ✅ 확인 |
| 홀 검출 위치 · 종류 (육안) | ✅ 확인 |
| **편차값 정확도** | ❌ **미검증** |
| **형상 분류 임계값 타당성** | ❌ **미검증** |

- **편차값**: 스캔 이미지의 숫자 라벨이 정답값이므로 색 역변환 결과와 대조할 수 있으나
  아직 수행하지 않았다. 컬러바 캘리브레이션이 맞는지 확인되지 않은 상태다.
  격자 샘플링 시 공차 초과 비율이 80%대로 높게 나오는데, 원본에 양품(회색) 라벨도
  상당수 있는 점을 고려하면 캘리브레이션 오차 가능성이 있다. 원인 규명이 필요하다.
- **형상 분류 임계값**: 비드/평면을 가르는 릴리프 국소 표준편차 기준(26, 8)과
  원형도 기준은 결과를 눈으로 보며 맞춘 값이다. 정량적 근거는 없다.

**다음 작업의 최우선 항목은 라벨 실측값과의 대조를 통한 편차 정확도 검증이다.**


## 구조

```
mold-correction-demo/
├── depth_measurement/          ← 본 파트
│   ├── streamlit_app.py        UI · 탭 구성
│   ├── pipeline.py             영상처리 · 검출 · 결합 로직 (단독 실행 가능)
│   ├── requirements.txt
│   └── README.md
└── data/sample/                샘플 스캔 이미지 (git 제외)
```

`pipeline.py` 는 UI 없이 단독 실행할 수 있다.

```bash
python depth_measurement/pipeline.py "data/sample/스캔.png" data/output/depth_measurement
```

단계별 결과 PNG 와 검출 개수, 처리 시간을 출력한다.

### 다른 파트와의 관계

- **`deviation_extraction`** — 라벨이 붙은 지점의 편차를 VLM 으로 판독한다.
  본 파트의 ⑤ 편차 조회는 컬러바 역변환으로 **라벨이 없는 지점까지** 값을 채우는 방식이라
  정밀도는 낮고 밀도는 높다. 두 결과는 경쟁이 아니라 상호보완적이다.
- **`label_removal`** — 본 파트의 ① 형상 추출에도 라벨 제거가 포함되어 있다.
  형상 특징 검출의 전처리로 필요해 자체 구현했으나 기능이 중복되므로,
  통합 시 한쪽으로 정리하는 것이 좋다.

   컬러바 캘리브레이션을 보정한다. 우선순위 최상.
2. **편차 × 형상 특징 결합** — 좌표 단위 통합 테이블과 CSV 내보내기
   (`pipeline.build_point_table` 에 구현되어 있으나 UI 미노출)
3. **0-라인 자동 생성** — 편차장의 `|편차| = 공차` 등고선으로 보정 영역 경계 산출
4. **CAD 정합** — ④에서 검출한 홀을 랜드마크로 특징점 기반 2D 정합. 3D 좌표와
   정확한 형상 치수(필릿 R 등)를 확보한다. **CAD 파일 확보가 선행 조건.**
5. **보정치 산출** — 형상별 계수를 실무 데이터로 역추정한 뒤 `−편차 × 계수` 적용

### 회사에 요청할 자료

- **CAD 원본** — 4번 정합의 선행 조건. 형상 치수를 추정이 아닌 설계값으로 대체한다.
- **3D 스캔 원본 데이터** (GOM/ATOS 리포트 · 점군) — 현재는 스캔 결과를 사람이 보도록
  렌더링한 **스크린샷**을 입력으로 쓰고 있다. 원본에는 좌표와 편차가 이미 수치로 들어 있어
  컬러바 역변환과 라벨 판독 자체가 불필요해진다.
