# 제로라인 학습 로드맵 — 지금 된 것 / 안 된 것 / 필요한 것

`README_zero_points.md` 가 "왜 라벨 실측값 방식인가"를 설명한다면, 이 문서는
"학습(ML)까지 가려면 뭐가 있고 뭐가 없는가"를 정리한다.

## 원칙 (반복 확인됨)

시트 좌표는 **정답(label)** 으로만 쓴다. 모델 입력(feature)은 3D스캔
실측값에서만 뽑는다 — 컬러바 색, 편차 포인트 값, 그 값들의 공간적 분포.
"선이냐 면이냐"도 규칙으로 정하지 않고 학습 대상으로 남겨둔다. (현업 확인
2026-08-25, 재확인 2026-08-25)

## 완료 — 지금 데이터(부품 3개)로 할 수 있었던 것

1. **JD_71XX2 보정시트 등록** — 파일명이 다른 두 부품과 달리
   `JD_71XX2-DR000 보정 시트.png`(중간에 띄어쓰기)라 이전엔 자동 등록이
   조용히 실패해 있었다. 파일명 확인 후 등록 완료 — `areas`(존 5개),
   좌우반전. `zero_line_library.json` 에 반영됨.

2. **후보 라벨링 파이프라인** (`ml_dataset.py`) — my_lab이 뽑은 0포인트
   후보마다 보정시트 정답과의 거리를 재서 양성/음성 라벨을 자동으로
   붙인다. 특징은 |편차|(3단계 스무딩), 기울기(3단계), 부호경계까지
   거리, 부품테두리까지 거리, 국소표준편차, 기존 규칙의 강도값 — 전부
   스캔에서만 계산. 시트 좌표는 라벨을 매기는 데만 쓰고 특징에는 안 넣음.

   허용오차(`tolerance_px=45`)는 실측으로 골랐다 — 후보-정답 거리를
   재보면 3부품 모두에서 진짜 근처(5~35px)와 완전히 딴 곳(80px 이상)
   사이에 뚜렷한 틈이 있었다.

   결과: 총 38개 후보(양성 13 / 음성 25) → `ml_data/candidate_dataset.csv`

3. **학습·검증 하네스** (`train_zero_classifier.py`) — scikit-learn 없이
   numpy 로지스틱회귀(L2 정규화) + leave-one-part-out 검증. AUC는
   순위-합 공식으로 직접 계산(scipy만 사용). 최종 가중치는
   `ml_data/classifier_weights.json` 에 저장만 하고 **서버에는 연결
   안 함**.

### 스모크테스트 결과 (참고용 — 통계적으로 못 믿음)

| held-out 부품 | 후보 수 (양성) | AUC | TP | FP | FN | TN |
|---|---|---|---|---|---|---|
| 64XX2 | 12 (4) | 0.56 | 2 | 2 | 2 | 6 |
| 67XX6 | 18 (7) | 0.75 | 2 | 0 | 5 | 11 |
| 71XX2 | 8 (2) | 0.67 | 0 | 1 | 2 | 5 |

3개 중 2개 폴드에서 AUC가 0.5(무작위)보다 뚜렷이 높다 — `feature_study.py`
에서 확인한 "신호는 있다"는 결론과 방향은 맞는다. 다만 폴드당 표본이
8~18개뿐이라 이 숫자 자체를 근거로 쓰면 안 된다. **코드가 도는지
확인하는 용도일 뿐이다.**

## 아직 안 된 것 + 필요한 것

| 안 된 것 | 왜 안 되는가 | 필요한 것 |
|---|---|---|
| **선/면(line vs zone) 판단 학습** | 부품 단위 라벨이 3개뿐(64=line, 67=area, 71=area) — 이진분류를 학습할 최소 표본조차 안 됨 | 부품 다양성 확대. line/area 각각 최소 5개 이상, 즉 부품 10개 이상 |
| **신뢰할 수 있는 성능 지표** | leave-one-part-out 폴드당 후보 8~18개라 우연 변동이 큼 (위 표) | 부품 15~20개 이상. `train_zero_classifier.py` 의 `MIN_PARTS_TO_TRUST` 로 이미 게이트해둠 |
| **프로덕션 랭킹에 모델 점수 반영** | n=3 모델이 지금 규칙(`connect_strongest_pair`)보다 못할 가능성이 높음 | 위 두 항목이 먼저 해결돼야 함. 그 전엔 가중치 파일만 쌓아두고 서버엔 안 붙임 |
| **끝점(시작/끝) 자동 선택 정확도** | 지금은 "가장 강한 부호전환 2개"인데, 실측(JD_64XX2)에서 진짜 끝점이 강도 순위 6위·3위였음 — 못 맞음 | 분류기 점수로 랭킹을 대체할 수 있을 만큼 데이터가 쌓이면 재검토 |
| **새 사례 반영 자동화** | 새 부품이 들어올 때마다 `my_lab` 4단계 수동 실행 → `zero_points_data/<품번>.json` 수동 배치 → `register_sheet.py` 수동 등록 → `ml_dataset.py`/`train_zero_classifier.py` 수동 재실행 | 이 네 단계를 묶는 파이프라인 스크립트. 지금은 부품 3개라 수동으로도 충분하지만 10개 이상 들어오면 병목이 됨 |

## 새 사례가 들어오면 할 일 (순서)

1. `my_lab/` 4단계를 새 부품 스캔에 대해 돌려 `zero_points.json`,
   `scan_point_loops.json` 생성
2. `zero_points_data/<품번>.json` 로 복사
3. `python -m zero_line_detection.register_sheet --scan ... --sheet ...`
   로 보정시트 정답 등록 (파일명에 공백·오탈자 없는지 먼저 확인 — 71XX2
   에서 이걸로 한 번 막혔었다)
4. `ml_dataset.py` 의 `CASES` 리스트에 부품 추가
5. `python -m zero_line_detection.ml_dataset` → `train_zero_classifier`
   재실행, `MIN_PARTS_TO_TRUST` 넘었는지 확인
